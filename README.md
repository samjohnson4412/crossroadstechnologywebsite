# crossroadstechnology.co

The Crossroads Technology website. Static HTML generated by a small
dependency-free Node script, built for search visibility and speed.

**Positioning:** *Designed, installed and supported by the same team.* Every
page is written from the premise that the people who scope the work are the
people who install and support it, and that one contractor covers the whole
stack. Deliberately not "built by techs, not salespeople" — that defined the
company by a negative and read as field labour to the buyers this has to win.

---

## Quick start

```bash
node build.js       # generate dist/
node validate.js    # check SEO, links, schema, escaping
npm run dev         # build and serve on http://localhost:8080
```

There are **no dependencies to install**. Node 18 or newer is the only
requirement, and `npm run dev` borrows `http-server` on demand.

---

## Why it is built this way

A brochure site's job is to load instantly and be legible to search engines.
Frameworks work against both. So:

| Decision | Reason |
| --- | --- |
| Hand-rolled generator, zero npm dependencies | Nothing to audit, upgrade, or break. The build cannot fail because of someone else's release. |
| No JavaScript on the rendered pages | The mobile menu is a CSS checkbox; the FAQ accordions are native `<details>`. Nothing to block rendering or hydrate. |
| System font stack | Zero font requests, zero layout shift, no flash of unstyled text. |
| Inline SVG icons, SVG logo | Two network requests per page: the HTML and one stylesheet. |
| Content in one data file | Phone number, address and hours appear in many places. They are defined once, so they cannot drift out of sync — which matters for local SEO. |

Home page: **~11.7 KB gzipped HTML + 5.1 KB CSS**, including the inline
vector hero. Interior pages are around 6 KB.

## Project structure

```
build.js              Generator: writes dist/, icons, OG image, sitemap, robots
validate.js           Post-build checks (run this before every deploy)
src/
  data.js             ALL business facts and page content  <- edit this
  pages.js            Page templates (home, service, industry, area, legal)
  layout.js           HTML shell, header, footer, JSON-LD structured data
  ui.js               Icons and small reusable components
  styles.css          The entire stylesheet
  assets/logo.svg     Official brand logo, unmodified
dist/                 Build output (git-ignored)
```

## Editing content

**Almost everything lives in `src/data.js`.**

- **Phone, email, address, hours** — the `site` object. Change once; it updates
  the header, footer, contact page, and the `LocalBusiness` structured data.
- **Services** — the `services` array (11 of them). Each entry generates a
  page at `/services/<slug>/`, a card on the services index, a footer link, a
  sitemap entry, and `Service` + `FAQPage` schema. `category` places it in one
  of the four `serviceCategories` groups — Network & Infrastructure, Security
  Systems, Managed IT & Cloud, Audio Visual, rendered in that order.
  `featured: true` also shows it on the home page, which carries eight.
- **Industries** — the `industries` array, same pattern.
- **Service areas** — the `areas` array, same pattern.
- **Home page FAQs** — `homeFaqs`. These carry the FAQ rich-result markup.

### Adding a new service page

Append an object to `services` in `src/data.js` with `slug`, `title`, `h1`,
`metaTitle`, `metaDescription`, `blurb`, `icon`, `intro`, `body`, `faqs` and
`related`, then run `node build.js`. The page, its navigation links, its
structured data, and its sitemap entry are all generated.

Pick `icon` from the keys in `src/ui.js`.

> Write genuinely distinct copy for each page. Near-duplicate service or
> location pages are treated as thin content and can suppress the whole site.

**Deliberately not services:** carrier offloading, real estate tech and
green/energy work are discontinued. Office moves, new-location buildouts and
general residential are not sold as standalone services either — moves and
buildouts are covered inside the cabling page where they apply, and the only
residential work taken is home theater, which its own page states plainly so
it qualifies enquiries rather than inviting the wrong ones.

## Brand

Both colors are taken from the official logo and should not be changed.

| Token | Value | Use |
| --- | --- | --- |
| `--navy` | `#1b3f8f` | Primary brand color |
| `--navy-900` | `#0d1b3d` | Dark sections, hero, footer |
| `--cyan` | `#0ab9e4` | Accent, on dark backgrounds |
| `--cyan-ink` | `#06758f` | Cyan **text** on light backgrounds |

### Motion

Restrained by intent: a 9s breathe on the dome, staggered signal-ring pulses,
and a short slide as sections enter (CSS scroll-driven, no JavaScript). The
reveal animates **transform only, never opacity** — a scroll-driven opacity
fade leaves everything below the fold at `opacity: 0` until someone scrolls,
and a crawler that renders without scrolling sees a blank page. Do not add
opacity back into `revealUp`. All motion is disabled under
`prefers-reduced-motion`.

`--cyan-ink` exists because brand cyan on white is only 2.3:1 — below the
WCAG AA minimum. Use it wherever cyan appears as text on a light background;
use `--cyan` on dark. All rendered text has been checked at 4.5:1 or better.

## Deploying

The output is plain static files. Any host works.

**Cloudflare Workers** (the current default for new static sites):

- Build command: `node build.js`
- Deploy command: `npx wrangler deploy`
- No environment variables needed

`wrangler.jsonc` in the repo root points Workers at `dist/` and serves
`404.html` for unknown paths. There is no Worker script — it is a static
asset deployment.

**Cloudflare Pages / Netlify** (if you use the older Pages flow instead):

- Build command: `node build.js`
- Output directory: `dist`
- No environment variables needed
- Cloudflare Pages additionally wants `pages_build_output_dir = "dist"` in a
  `wrangler.toml`; the Workers-style `wrangler.jsonc` here is not valid for a
  Pages project, so delete it if you go that route.

`dist/_headers` sets cache and security headers, and `dist/_redirects`
preserves the old `/privacy.html` and `/returns.html` URLs. Both files are read
automatically by Cloudflare Pages and Netlify. On another host, port those
rules to its equivalent config.

Run `node validate.js` before deploying. It fails the build on broken internal
links, duplicate titles, missing canonicals, malformed JSON-LD and unescaped
markup.

## Before launch

- [ ] **Wire up the contact form.** It currently falls back to opening the
      visitor's mail client. Set `formEndpoint` in `src/data.js` to a handler
      URL (Formspree, Netlify Forms, or Zoho Forms — Zoho is already in use for
      ticketing) and the form will post directly.
- [ ] **Confirm the published details.** Phone `(813) 921-5733` and the Camden
      Bay address were taken from existing public listings. Verify they are
      current, and decide whether `sales@` is the right inbox.
- [ ] **Replace `og.png`.** The build generates a branded gradient card with no
      text. A designed 1200×630 card with the logo and tagline will convert
      better when links are shared. Drop it in and the build will keep it if
      you remove the generator call, or just overwrite the file after building.
- [ ] **Swap client wordmarks for logos.** The "Trusted by" strip renders the
      four client names as text. Real logo files would look stronger.
- [ ] **Add testimonials.** Two real quotes would lift conversion more than
      anything else on the page. Nothing was invented for this build — every
      claim on the site is one the company can stand behind.
- [ ] **Google Business Profile.** The single highest-leverage local SEO action.
      Ensure the name, address, phone and hours exactly match `src/data.js`,
      pick the right primary category (likely "Computer support and services"),
      and start collecting reviews.
- [ ] **Google Search Console.** Verify the domain and submit
      `https://crossroadstechnology.co/sitemap.xml`.
- [ ] **Check redirects.** If the old site had URLs beyond `/privacy` and
      `/returns`, add 301s for them to `dist/_redirects` via `build.js`.

## After launch

- Each service page targets a distinct commercial query; each area page targets
  a local one. Watch which ones earn impressions in Search Console and expand
  the pages that gain traction rather than adding new thin ones.
- The FAQ blocks are eligible for rich results. Adding real questions clients
  ask is cheap and effective.
- Keep the NAP identical everywhere it appears online. Inconsistent citations
  are the most common cause of weak local rankings.
